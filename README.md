# nspawn.org

The source of [nspawn.org](https://nspawn.org): the landing page and the
documentation of [nspawn](https://github.com/nspawn/nspawn), the docker-like
tool for systemd-nspawn machines, and of the image hub.

The site is built with [Hugo](https://gohugo.io/) and the
[Docsy](https://www.docsy.dev/) theme, pulled in as a Hugo module together with
its npm dependencies.

## Preview with nspawn

Nothing but [nspawn](https://nspawn.org/docs/getting-started/#installation) is
needed on the host:

```shell
sudo nspawn compose up
```

Open <http://localhost:1313>. Edits under `content/`, `assets/` and `layouts/`
reload live. The first start installs the npm packages into `node_modules/`
and downloads the Hugo module and the Hugo binary; the caches live in an nspawn
volume, so later starts are quick.

The machine runs as uid and gid 1000 so that `node_modules/` and the build
output belong to you. If yours differ, pass them along:

```shell
sudo env SITE_UID=$(id -u) SITE_GID=$(id -g) nspawn compose up   # bash, zsh
sudo env SITE_UID=(id -u) SITE_GID=(id -g) nspawn compose up     # fish
```

## Preview without nspawn

Install Node.js (see `.nvmrc`), npm, Go and git; Hugo itself comes from the
pinned `hugo-extended` npm package. Then:

```shell
npm run install:safe   # lock-exact, script-free install
npm run serve
```

Run Hugo through the npm scripts: they put the Dart Sass binary from
`node_modules` on the `PATH`, and a bare `hugo` invocation fails without it.

## Layout

| Path | Contents |
| --- | --- |
| `hugo.yaml` | Site configuration: title, menu, footer links, search, theme parameters. |
| `content/en/` | The pages. `_index.md` is the landing page, `docs/` the documentation, `about/` and `community/` the other top-level pages. |
| `assets/scss/` | Colors (`_variables_project.scss`) and project styles (`_styles_project.scss`). |
| `assets/icons/logo.svg` | The navbar logo; `static/` holds the favicons. |
| `layouts/` | Overrides of the theme's templates. |
| `packages/hugoautogen/` | Generated manifest of the theme's npm dependencies; regenerated by `npm run update:docsy:pack`. |
| `tests/` | Checks run by `npm run test:site` on the built site. |

Documentation pages are Markdown with front matter; `weight` orders them in the
sidebar and `description` is shown in the section index.

## Build

```shell
npm run build:production
```

writes the site to `public/`. The `build and deploy` workflow builds the site
on every push and pull request and keeps the result as an artifact.
